# 프론트엔드 테스트 시나리오

Mock 음성 파일은 실제 전송·인식하지 않는다. 파일명의 별칭이 일치하면 해당 시나리오로, 일치하지 않으면 파일명·크기·수정 시각의 안정적인 fingerprint로 성공 시나리오 중 하나에 매핑된다.

| 시나리오 | 파일명 예시 | 예상 업무 | 특수 조건 | 성공 판정 |
|---|---|---:|---|---|
| 01 제안서와 견적 | `call-01.mp3`, `proposal.wav` | 4 | 제안·견적·예산·후속 통화 | 4개 업무와 제안서 요청 단계 표시 |
| 02 담당 부서 불일치 | `call-02.m4a`, `정보화.wav` | 4 | 새로운 업무명, 의사결정자 탐색 | 정보화 담당 부서 연결 업무 표시 |
| 03 현재 도입 거절 | `call-03.mp3`, `budget.wav` | 4 | 장기 보류, 자동 실행 경고 | 거절 맥락과 재접촉 업무 표시 |
| 04 추천 업무 없음 | `call-04.wav`, `wrong-number.mp3` | 0 | 빈 배열 | 명시적인 0개 안내와 직접 추가 버튼 표시 |
| 05 다수 요청 | `call-05.mp3`, `many.m4a` | 9 | 8개 이상, 새로운 업무명 | 내부 스크롤로 9개 모두 접근 가능 |
| 06 정보 부족 | `call-06.wav`, `limited.mp3` | 1 | 빈 요구·우려, 낮은 신뢰도, 기한 없음 | 빈 섹션을 숨기고 단일 확인 업무 표시 |
| 07 분석 실패 | `call-07.mp3`, `failure.wav` | 오류 | Mock 예외 | 실패 안내, 다시 시도, 녹취록 이동 표시 |
| 08 스트레스 | `call-08.m4a`, `stress.wav` | 8 | 긴 텍스트, 11개 요구, 5개 근거, 11개 자료, 비정상 신뢰도·실행 방식 | 화면 중단 없이 clamp 및 일반 업무 처리 |

## 공통 조작 테스트

- 파일 선택 직후 녹취 상태가 `processing`이 되고 textarea와 분석 버튼이 비활성화된다.
- Mock 녹취 완료 후 동일한 textarea에 결과가 표시되고 출처가 `mock`으로 표시된다.
- textarea를 수정하면 출처가 `user`로 바뀌고 원본 출처는 `originSource`에 유지된다.
- 수정된 녹취록으로 분석을 실행할 수 있다.
- AI 추천 업무를 선택한 후 업무명·설명·우선순위·기한·필요 자료를 수정하면 `사용자 수정됨`이 표시된다.
- 사용자 업무를 직접 추가하면 `사용자 추가` 출처가 표시되고 AI 신뢰도는 표시하지 않는다.
- 업무를 승인·보류·거절할 수 있으며 거절 업무가 목록과 저장 데이터에 남는다.
- 다른 시나리오 또는 파일을 선택할 때 검토 중인 변경이 있으면 초기화 확인을 요청한다.
- 새 분석 시작 시 이전 결과와 선택 목록이 제거된다.
- 빈 녹취록은 분석 버튼이 비활성화되고 안내가 표시된다.
- 짧은 녹취록은 분석 결과 경고에 정확도 안내가 추가된다.
- 개발용 진단 영역에서 현재 시나리오, 업무 개수와 원본 Mock JSON을 확인한다.

## 성공 기준

모든 시나리오에서 흰 화면, 잘린 카드, 접근 불가능한 버튼, 콘솔 오류가 없어야 한다. 데스크톱 3열과 390px 모바일 1열에서 입력 → 분석 → 업무 검토 순서를 유지해야 한다.
