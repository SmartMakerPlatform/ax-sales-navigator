# 요구사항

## 핵심 사용자 흐름

파일 또는 샘플 시나리오 선택 → 녹취록 확인·교정 → 분석 요청 → 요약과 영업 정보 확인 → 동적 추천 업무 선택 → 세부 내용 수정 → 승인 또는 보류 → 승인 업무를 브라우저에 저장한다.

## 기능 요구사항

- M4A, MP3, WAV 파일 정보 표시
- 서로 다른 세 개 이상의 샘플 녹취록과 분석 결과
- 1~2초의 Mock 분석 상태 및 중복 요청 방지
- 분석 성공·실패, 선택·수정·승인·보류·저장 상태 표시
- 요약, 요구, 반대 의견, 약속, 확인 항목, 영업 단계, 경고 표시
- 추천 업무 상세 근거, 필요 자료, 기대 결과 표시
- 업무명, 지시, 우선순위, 기한, 필요 자료 수정
- 승인 업무만 LocalStorage에 저장
- 데스크톱 3열 및 모바일 1열 반응형 배치

## 데이터 구조

`frontend/src/types/analysis.ts`의 `CallAnalysisResult`, `RecommendedAction`, `PromiseItem`, `Evidence`를 기준으로 한다. 화면과 Mock 서비스는 동일 타입 계약을 사용한다.

## 동적 업무 제안 원칙

업무명과 설명은 고정된 유형 목록이 아니다. 프론트엔드는 `recommendedActions`를 순회해 공통 카드로 렌더링하며, 처음 보는 `label`도 그대로 표시한다. `executionMode`는 표현 및 향후 연결을 위한 힌트일 뿐 업무를 제한하지 않는다.

## Human-in-the-loop

AI는 제안만 한다. 사용자가 선택하고 내용을 검토·수정한 뒤 명시적으로 승인한 업무만 저장한다. 이메일 발송, 일정 등록 등 외부 실행은 자동 수행하지 않는다.

## PoC 성공 기준

세 시나리오의 분석·업무가 달라야 하며, 임의의 새 업무명도 카드에 표시되어야 한다. 업무를 수정·승인하고 LocalStorage에 저장할 수 있어야 한다. Mock 구현을 API 구현으로 교체해도 UI를 수정할 필요가 없어야 한다.
